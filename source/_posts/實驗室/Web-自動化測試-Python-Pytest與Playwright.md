這篇是「網站品質與軟體測試」系列的第三階段。目標不是證明我會寫幾支瀏覽器腳本，而是挑出穩定、重複價值高的案例，讓電腦協助執行回歸測試，並在失敗時留下足夠證據。

> **資料狀態：建立工具學習順序，尚未完成可重複執行的測試專案**

## 本單元一定要會

- 能用 Python、Pytest 與 Playwright 從命令列執行瀏覽器測試。
- 能使用穩定的 Locator 完成基本操作，並用 Assertion 驗證需求結果。
- 能把至少 5 個手動案例轉成可執行測試，並說明哪些案例值得自動化。
- 能在一次測試失敗時留下截圖或 Trace，知道如何查看失敗證據。

### 本單元先不學

JavaScript／TypeScript、API 測試、跨瀏覽器矩陣、Docker 與複雜框架抽象先不加入；先讓一條小而穩定的 Web 測試流程跑通。

### 過關條件

在不含工作機密的練習專案中，從乾淨環境執行至少 5 個測試，並在 README 寫清楚安裝方式、執行指令、測試範圍與已知限制。只貼程式碼、不知道怎麼重跑，不算過關。

## 為什麼先用 Python + Pytest + Playwright

我已經有 Python 基礎，也希望先把手動測試與 Web 自動化接起來，因此第一輪不再同時增加 JavaScript、Appium、Maestro 等新工具。先用一組範圍清楚的技術完成最小可行專案，比收集很多工具名稱更能看出自己是否真的理解測試。

## 學習順序

### 1. 先讓瀏覽器完成最小流程

先做到：開啟瀏覽器、進入測試頁面、找到元素、執行一個操作、關閉瀏覽器。這一步的目的是確認環境、瀏覽器與測試資料可以運作，不急著設計複雜框架。

### 2. 學會定位、操作與驗證

目前先整理這組基本能力：

```text
page.goto()
get_by_role() / get_by_text() / locator()
click() / fill()
expect(...)
```

真正要理解的是：定位方式是否穩定、操作後要觀察什麼、Assertion 是否真的對應需求，而不是把 API 名稱背起來。

### 3. 接回 Pytest

把不同情境拆成容易理解的測試函式，例如登入成功、錯誤密碼、搜尋與基本導覽。每個測試都應該有清楚的目的、前置資料與可判斷的結果。

### 4. 再學維護性

當測試能跑後，再加入：

- **Fixture**：集中處理測試前準備、測試執行與清理。
- **Parameterization**：用多組資料重複執行同一測試，不複製整份程式。
- **Screenshot／Trace**：失敗時保留畫面、步驟與紀錄，方便回溯。
- **Page Object Model**：把頁面定位與操作整理在適當的物件中，降低測試案例互相綁死。

## 從手動案例挑自動化對象

不是每個 Test Case 都值得自動化。第一輪優先選：

- 需求穩定、近期會反覆執行的流程。
- 操作步驟固定、預期結果明確的案例。
- 失敗會影響主要使用路徑的案例。
- 人工重複執行成本高，但自動化後容易維護的案例。

先把第一階段的登入成功、錯誤密碼與搜尋案例各挑一個，完成 3 個最小測試；再補到至少 5 個，並記錄哪些案例刻意保留手動執行，以及原因。

## 建議的練習專案結構

```text
qa-demo/
├─ README.md
├─ requirements.txt
├─ pages/
│  ├─ login_page.py
│  └─ search_page.py
├─ tests/
│  ├─ test_login.py
│  └─ test_search.py
└─ testcases/
   └─ test-cases.md
```

這只是起始結構，不代表每個專案都必須使用 Page Object Model。當測試數量很少或頁面仍頻繁變動時，過早抽象也可能增加理解成本。

## 自動化測試不能替代的事情

- 需求是否合理，仍需要產品與使用者脈絡。
- 視覺、內容、無障礙與可理解性，不能只靠幾個 DOM assertion 判斷。
- 測試通過只表示特定條件下的檢查通過，不代表整個產品沒有問題。
- 不穩定的定位器、共享狀態與不乾淨的測試資料，會讓失敗結果失去可信度。

## 這篇的實作作業

1. 建立一個不含工作機密的練習專案。
2. 先讓瀏覽器成功開啟並執行一個簡單操作。
3. 寫出 5 個可以執行的自動化測試，至少涵蓋成功與失敗情境。
4. 加入一組參數化測試與一個失敗證據輸出。
5. 將至少一個頁面的操作整理成 Page Object，並在 README 說明測試範圍與限制。

## 還沒回答的問題

- 什麼情況下 locator 算穩定？
- 測試資料要如何建立、重置與隔離？
- 測試失敗時，如何區分產品缺陷、測試腳本問題與環境問題？
- 哪些工作上的規則檢核適合當作 API 或資料層測試，而不是瀏覽器測試？
