這是一篇把工作事件去脈絡化後留下的上稿紀錄。人物、單位、網址、檔名與個案內容都不放進來，只保留今天在處理網頁內容、附件與表格時，值得之後重複使用的判斷方法。

今天最深的感覺是：上稿看起來像是把內容放進後台，實際上卻同時在處理 HTML 結構、編輯器行為、前台樣式、表格資料與檔案權限。只要其中一層沒有確認，最後呈現就可能和預期差很多。

# 後台寫得標準，為什麼前台看起來還是差很多？

「後台都是標準的」通常代表內容使用了合乎規範的 HTML，例如一般段落使用 `<p>`。但 HTML 標準主要處理的是內容結構，不會單獨決定最後的視覺效果。

同一段 `<p>`，放在不同的容器、套用不同的 CSS，可能會有不同的：

- 字型、大小與行高。
- 寬度、邊界與換行方式。
- 粗體、顏色與底線範圍。
- 段落前後的間距。
- 在桌機與手機上的排列方式。

所以看到「後台標準、前台卻不一樣」時，不應立刻判斷是 HTML 標準失效，而要拆成兩個問題：

1. 內容結構是不是正確？
2. 前台樣式是不是依照預期套用？

後台編輯器顯示正常，也不代表實際輸出的 HTML 和預期完全相同。編輯器可能會自動補標籤、調整巢狀結構、保留貼上來源的樣式，或在儲存時重新整理部分內容。

# `<span>` 沒有框住整個字，問題可能在哪裡？

這類問題通常不是「顏色設定錯了」，而是標籤範圍沒有包住完整文字。例如顏色、底線或其他效果是加在 `<span>` 上，但結尾的 `</span>` 太早出現，後面的字就不在這個範圍內。

排查時可以依序確認：

- `<span>` 是否有成對出現。
- 開始與結束標籤中間是否包含完整文字。
- 標籤是否被另一個段落或連結切斷。
- 編輯器儲存後，原始碼是否被重新排列。
- 前台是否有更高優先權的 CSS 蓋過原本設定。

因此，不能只看畫面猜原因。畫面只能告訴我們「效果沒有完整出現」，原始碼才能確認是範圍、巢狀結構，還是 CSS 優先權出了問題。

# 表格為什麼特別難處理？

表格比一般文字麻煩，是因為它不是一段文字，而是一個帶有結構與狀態的元件。除了儲存格內容，還可能同時帶著：

- 欄寬與列高。
- 合併儲存格。
- 邊框、背景色與對齊方式。
- 內嵌樣式或編輯器產生的屬性。
- 舊資料、隱藏欄位與原本的表格結構。

如果直接複製既有表格再修改，表面上看起來只是換文字，實際上可能把原本的欄寬、合併方式、樣式甚至資料一起帶過來。尤其在「不重建」的情況下，舊設定很容易藏在原始碼裡，直到前台呈現或後續修改時才暴露出來。

這也是為什麼表格常常會出現「看起來改好了，但原始碼還有其他問題」的情況：眼前的文字已經換掉，結構卻沒有真正清乾淨。

# 遇到表格，什麼時候應該重劃？

如果只是修改同一個表格裡的少量文字，而且欄列結構確定沒有變，可以先保留原表格，再檢查輸出的 HTML。

但只要出現下面情況，就應該優先考慮重新建立乾淨的表格：

- 欄數或列數和原本不同。
- 合併儲存格需要改動。
- 新舊表格的欄寬、邊框或對齊方式不同。
- 複製來源不明，無法確認帶了哪些設定。
- 前台出現錯位、內容重複或手機版難以閱讀。
- 原始碼中有大量看不懂的內嵌樣式。

重劃不是浪費時間，而是在用明確的結構換取後續可控性。表格若已經混入太多舊設定，繼續在原本的結構上修補，常常比重建更花時間。

# 不能下載的檔案，不能只看「能不能放上去」

上稿時也可能遇到「可以觀看，但不希望直接下載」的內容。這時要先分清楚需求到底是哪一種：

- 只提供外部檢視連結。
- 將原始檔案上傳到網站，但不在頁面上提供下載按鈕。
- 需要遵守提供者設定的觀看權限。
- 需要留下來源，但不能改變原本的使用方式。

這些選項的權限意義不同。不能因為網站可以放檔案，就直接把原本的觀看連結轉成公開下載，也不能只看到「附件放上去了」就認定需求完成。

比較穩妥的做法是先確認：

1. 提供者允許的使用方式是什麼？
2. 使用者需要觀看、下載，還是兩者都要？
3. 內容放在外部服務或本站，哪一種才符合原本的權限？
4. 頁面上的說明是否要清楚標示檔案用途與限制？

這一類問題表面上是上稿，實際上也包含內容授權與使用者期待，不能只用技術方便與否來決定。

# 今天比較有效的排查順序

之後遇到類似的上稿問題，我會按照下面的順序處理：

## 先保留原始狀態

修改前先截圖、複製原始碼或保留原始檔案。尤其是表格，更新後如果才發現結構被改掉，沒有原始狀態就很難比較是哪一步造成差異。

## 再分開看內容與呈現

先確認文字、連結、表格資料本身是否正確，再確認 CSS、版面寬度、換行與手機版呈現。不要把「資料正確」和「畫面好看」當成同一件事。

## 看到異常就查看原始碼

遇到顏色範圍不完整、文字突然變大、表格錯位或樣式不一致時，要查看實際輸出的 HTML，而不是只在編輯器裡反覆嘗試。

## 複製內容後檢查隱藏設定

複製表格、段落或附件區塊時，要把它當成「複製結構」而不是「複製文字」。如果來源不乾淨，重建通常比逐一猜測舊設定更可靠。

## 最後用前台情境驗證

至少要檢查桌機、手機、不同長度的文字、表格資料、連結與附件權限。後台預覽通過，只能代表編輯器能顯示，不能代表公開頁面的所有情境都正常。

# 今天留下來的工作原則

1. **標準 HTML 解決的是結構，不保證視覺呈現完全一致。**
2. **看到樣式範圍不完整，先查標籤範圍與巢狀結構。**
3. **表格不是普通文字；複製時會連同舊設定一起被帶過來。**
4. **當表格結構已經不確定，重劃往往比繼續修補安全。**
5. **檔案能不能上稿，和使用者能不能下載，是兩個不同的問題。**
6. **後台完成不等於上稿完成，公開頁面驗證才是最後一步。**

今天也很明顯感覺到，這種工作不能只靠一直坐著盯畫面解決。上稿細節很多，坐得越久、疲勞越高，越容易漏掉一個結尾標籤、一個舊欄位或一個權限差異。之後可以把工作切成幾個小段，在每個段落完成時留下紀錄並起身休息，讓檢查不只靠最後一次總確認。

# 一句話整理

> **上稿不是把內容貼進後台，而是確認內容結構、前台呈現、表格狀態與使用權限，最後在公開頁面重新驗證。**
