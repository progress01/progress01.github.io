# 網誌載入效能優化 WBS

狀態：2026-10-02 作者改選 A 面文章清單加同頁標題／標籤搜尋；本機已完成替換並驗證，未部署  
適用專案：`C:\Blog\blog-1988`  
執行方式：有額度時一次只做一個可保存、可回復、可驗證的小工作包

## 1. 目標

在不改文章網址、內容、A／B 面用途與主要視覺的前提下，縮短首次開啟與手機網路較慢時的等待時間。優先處理首屏確實會下載的資源，不因檔案看起來很大就盲目重寫。

完成條件不是單看 lazy loading 是否存在，而是同一測試條件下的首屏時間、請求數與傳輸量有可重現的改善，且 A 面文章清單、B 面隨機卡、搜尋、返回與無障礙功能沒有退化。

## 2. 不可變更原則

1. 每次只執行一個工作包；完成實測與紀錄後才進下一包。
2. 保留文章 permalink、正文、microblog ID、A／B 面路由與既有未提交修改。
3. 不為追求分數移除讀者會使用的功能；若需改變動畫、分析或圖表呈現，先由作者決定。
4. 不把延遲載入做成空白首屏或版面跳動；無 JavaScript 與載入失敗時仍須有可理解內容。
5. 部署是獨立工作包，必須取得該次明確授權。
6. 不使用額度重置券，除非作者針對該次重置另行明確授權。

## 3. 2026-09-30 初步基準

以下是 fresh `public/` 與線上頁面的快速排查結果，只作為工作排序依據；正式比較仍以 WBS 0.1 的固定量測方式為準。

| 項目 | A 面 `/` | B 面 `/memory/` | 判讀 |
|---|---:|---:|---|
| 原始 HTML | 約 227.5 KB | 約 245.6 KB | GitHub Pages 傳輸時可能壓縮，不能只看原始檔判定 |
| 實際觀察到的 script | 17 | 13 | A 面多出圖表相關程式 |
| 主要 CSS | 約 121 KB | 約 121 KB | 共用資源，列為後段整理 |
| ECharts | 約 1,091.7 KB | 不載入 | A 面首要候選 |
| 全新快取桌機粗測 | 約 1.59 秒 | 約 1.22 秒 | 不是正式 Web Vitals，只證明 A 面負擔較高 |

其他觀察：

- `navigation-index.json` 約 1,996.2 KB、`search.xml` 約 1,550.6 KB；目前 `preload: false`，不會在進站時立即下載，搜尋效能排在首屏之後。
- NexT 全站 `lazyload` 設定目前為 `false`；部分文章列表圖片個別使用 `loading="lazy"`。B 面隨機卡封面由 JavaScript 在首屏選定後指定，延遲圖片本身不是 A 面慢的主因。
- A／B 皆依賴 cdnjs、Font Awesome、animate.css、anime.js 與 Google Analytics；第三方 DNS、TLS 或服務波動可能造成偶發等待。
- 公開圖片中仍有多個 1 MB 以上的 PNG／JPG，主要風險在文章頁與隨機抽到該封面時，需以「實際有被引用」為優先，不批次盲轉全部檔案。

1. A 面文章清單與同頁搜尋已在本機完成；後續需要量化整體改善時，再做 **0.1 建立可重跑基準**。

4. 每完成一包就在 [執行進度](personal-navigation-progress.md) 記錄修改、實測與下一步；未驗證不標完成。
