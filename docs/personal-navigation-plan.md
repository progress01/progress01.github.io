# 個人網誌動線改善：工作拆分與驗收

狀態：2026-09-14 已獲使用者確認；2026-09-28 依作者最新決定，根路由 `/` 改為 A 面，B 面固定於 `/memory/`，`/profile/` 保留為 A 面相容入口。下一步仍依 [執行進度](personal-navigation-progress.md) 一次處理一個可驗證小步驟。
規劃日期：2026-09-14（Asia/Taipei）

## 目標與範圍

服務最常使用網站的作者本人：記得部分內容時找得回來、返回列表時不迷失位置、能依時間回顧當時留下的不同紀錄。

保留首頁、主選單名稱、磁帶風格、圖牆點圖收聽、草稿夾與日曆的原有用途。優先擴充現有功能，不另外建立一套網站入口。既有文章 URL、日期、內容與未提交修改均須保留。規劃確認不等於部署授權。

## 執行方式

- 單次工作限一個可保存、可驗證的小步驟；大項目可以跨次完成。
- 不得使用任何額度重置券；只有使用者針對該次重置明確授權後才能使用，過往授權不得沿用。

## 工作項目

### 1. 資料盤點與驗收樣本（小）

產出：盤點文章、microblog.json、reading-desk.yml 與目前索引來源；定義紀錄識別、類型、日期、標題、內文與可開啟位置。保存既有工作樹基準，選取真實查找案例作為驗收清單。

驗收：文章、碎碎念、學習題目各有代表案例；相同文章被草稿夾引用時明確定義如何去重；沒有可靠日期的資料不猜日期；識別不靠會隨插入而變動的列表序號。確認未發布內容不會被意外加入公開索引。

停止點：資料對照表與案例完成，不變更介面。

### 2. 統一搜尋資料來源（中，依賴 1）

產出：利用現有靜態建置流程，讓搜尋涵蓋已公開的文章、碎碎念及學習題目。保留來源、分類、日期和目標連結，解決重複收錄。

驗收：逐一找出項目 1 的已知案例；同一篇文章不因多個入口重複顯示；新增或更新一筆來源後能隨建置更新；缺少選填欄位、空資料及載入失敗有明確處理。排除腳本、樣式與頁面裝飾文字干擾。

停止點：可驗證的索引與對應測試完成，保留原本搜尋使用方式。

### 3. 搜尋結果、篩選與精準定位（中，依賴 2）

產出：在現有搜尋視窗顯示來源、日期及命中片段，加入內容類型／分類與月份的縮小範圍方式。文章定位到可靠的命中段落，碎碎念與題目定位到對應紀錄；無法可靠定位時提供明確的頁面層級退回方式。

驗收：關鍵字與篩選同時有效；清空條件能恢復結果；中文、英文、特殊符號與無結果情境正常。從結果點進去可辨認命中內容；錨點在重新整理、直接開啟與跨次建置後有效，無重複 ID。

停止點：搜尋流程可單獨交付試用。

### 4. 返回保留原位置（中，依賴 3）

產出：搜尋、圖牆、草稿夾及日曆在返回時保留各自的條件、選定日期、必要的展開數量與位置。沿用瀏覽器上一頁習慣；狀態限本機分頁／瀏覽工作階段，不建立伺服器訪客追蹤。

驗收：從搜尋第幾筆點進文章再返回，仍看到同筆附近與原條件；從圖牆中段開啟內容再回來保留分類與位置；草稿夾與日曆保留日期。測試一般導覽與網站現有 PJAX、重新整理、直接開啟、多分頁互不污染及資料改變後的合理退回。

停止點：桌面與手機的返回流程可用，不必等待時間回顧完成。

### 5. 日曆整合同期紀錄（中，依賴 1、2、4）

產出：在現有日曆下方增加當天／一週／月份檢視，並列同時段的文章、碎碎念與學習題目，可按類型縮小範圍。維持熱力圖原有統計口徑，若要改口徑另行說明；列表清楚標示日期意義。

驗收：Asia/Taipei 下的跨月、跨年、閏日與一週邊界正確；發表日期、紀錄日期與更新日期不混為一談；不把文章發表日描述成事情實際發生日。同一文章去重，空日期與空月份可理解；點進內容後能返回原範圍。

停止點：能重現一段真實時期的紀錄清單，無需作者重標所有舊文章。

### 6. 補上頁面之間的小連結（小至中，依賴 4、5）

產出：文章日期附近加入「看看那一週」；N+天系列補系列前後篇與目錄；音樂圖牆保留點圖收聽，新增「我的心得」連結。配對採明確文章資料，遇到歧義不猜。

驗收：日期連結帶入正確週範圍；N+天排序遵循系列順序、缺篇與首尾篇正常；圖牆收聽網址完全保留，心得連到對應文章。手機點擊區域不衝突，鍵盤可操作，返回後位置仍保留；原有一般前後篇和相關文章無退化。

停止點：各入口可分別交付，不一次改整個版面。

### 7. 整體驗收與後續維護規則（小至中，依賴 2–6）

產出：執行整合驗收，整理操作說明、必要的既有維護指引補充與已知限制；提供本機預覽和修改清單供使用者試用。

驗收：完成「只記得一句話→找到→定位→返回」、「回顧某一週→跨類型閱讀→返回」、「圖牆聽歌／看心得」、「N+天連續閱讀」四條流程。桌面及 375px 手機檢查可讀性、點擊、鍵盤、捲動與溢出。執行 npm run verify 及本次變更的 diff 檢查；確認原文章 URL、正文、图片 alt、日期與既有功能保留。來源資料新增一筆後，相關索引能自動更新。

停止點：本機驗收完成、使用者可試用；部署須另有明確授權。

## 建議交付順序

1. 第一輪：項目 1、2、3，先解決找不到內容。
2. 第二輪：項目 4，讓找回內容後能順利返回。
3. 第三輪：項目 5、6、7，完成時間回顧與整體接續。

每輪可跨數次執行，不代表單次要全部完成。確認整體規劃後可在授權範圍內逐項推進；每項記錄實作、測試與待辦狀態，未完成驗證前不將項目標成完成。一般小改先跑對應檢查，每個可交付批次跑一次完整驗證；沒有新變更或失敗不重複整站檢查。
