# B 面：我正在練習的問題

狀態：依作者要求暫緩，待作者再思考。僅修復本篇文章的 QA 與修訂記錄；未新增 B 面功能，也未替其他文章建立清單。

作者最新理解：這些文章比較像「錯題集」，保留實際遇到但還不會處理的情況；能力缺口與制度缺口都是真的，不把所有問題歸為個人錯誤。下列入口、狀態與呈現形式都是尚未採用的發想，不繼續製作原型。

## 用途

「修行文章」可以留下我怎麼理解一個問題，也讓我回來找到尚未解決的部分。文章讀完之後，能知道下一次要試什麼；試過之後，能留下有效或無效的證據。

B 面保留既有個人記憶庫用途，增加「我正在練習的問題」入口。入口先列目前最想處理的三題，提供查看全部的連結。完整清單按議題或狀態查看，不替換歌曲、生活紀錄、日曆或抽籤。

## 每題的最小內容

| 項目 | 用途 |
| --- | --- |
| Q：我需要解決什麼？ | 用第一人稱寫出會反覆遇到的困難。 |
| A：目前怎麼理解？ | 保存暫定答案，允許以後修正。 |
| 下一次練習 | 一個能在實際情境試的動作。 |
| 回頭檢查 | 用什麼跡象判斷這次練習是否有幫助。 |
| 狀態與實際紀錄 | 由作者根據案例更新；沒有試過就不標完成。 |
| 來源文章 | 回到原文章的對應 QA，保留完整脈絡。 |

清單卡片先顯示問題、狀態、下一次練習與來源。暫定答案、回頭檢查和案例展開後閱讀，避免首頁每題都像一篇長文。

## 狀態如何變動

- 待釐清：還說不清卡點，或缺少需要的資訊。
- 練習中：有暫定做法，準備試或正在試，還沒確認能否重用。
- 已有可重用做法：留下具體案例，能說明有效的條件與限制。

作者可以重新打開任何一題。文章發表、寫出答案、沒有被質疑，都不自動改變狀態。先不設完成百分比、連續天數或積分。

## 用本篇作為範例

來源：`/work/learning-to-name-work-gaps/`。

優先練習的三題：

1. Q1：接到陌生任務時，我到底卡在哪裡？
2. Q3：我怎麼知道公司準備做到哪裡？
3. Q6：我的問題要怎麼問，對方才容易回答？

文章已有八題 QA 與 `work-gap-q1` 至 `work-gap-q8` 固定錨點。各題都還是暫定理解，沒有實際成效紀錄；草案不宣稱任何一題已解決。

若不同文章再次談到同一問題，未來可以讓同一題連到多篇文章，顯示理解如何變動。合併題目由作者確認，不能只靠相似標題自動合併。

## 與既有網站的關係

A 面「工作與學習」與 B 面「個人記憶庫」共用一份文章、一個網址。問題入口位於 B 面，連回原文，不複製另一篇 B 面文章。B 面也是公開網站；私人工作細節、對話與內部案例不因入口名稱而成為私人內容。

目前先以文章文末 QA 為內容來源。後續若做聚合，再規劃每題的固定識別、狀態、案例和來源位置，讓文章與清單由同一份資料生成，避免兩處手動維護。第一版不在瀏覽器勾選後宣稱全站狀態已儲存。

## 後續文章維護規則提案

- 正文按照思考脈絡寫，不必按照聊天日期寫。
- 文末保留個人問題清單和獨立修訂記錄。
- 「移除正文日期」不刪修訂記錄；「重整文章」不刪既有 QA。
- 修改 A 時保留理解改變的原因；宣稱有進展時附上實際練習紀錄。
- 只替作者認為值得持續練習的文章建立清單，不將所有文章套成同一格式。

## 下一個可驗收的小步驟

確認此方向後，先用本篇八題做 B 面問題入口的單篇原型，檢查是否能從入口找到三個優先問題、閱讀下一步、回到原文並查看修訂記錄。完成這個步驟，再考慮跨文章整理與狀態篩選。

## 本次修復驗收

修復後須確認原文輸出有八題 QA、三個優先題目、四筆修訂記錄及八個固定錨點，摘要與全站驗證通過。發布與線上核對結果以本次實際執行結果為準。
