網站上稿為什麼會出現兩次附件下載？先分清內文與 CMS 模組

發表於 2026-09-29 分類於 工作知識 文章字數： 1.8k 所需閱讀時間 ≈ 2 分鐘
收錄於 工作與學習・ 個人記憶庫

正式頁面出現兩次一模一樣的附件下載區塊時，問題不一定是 HTML 寫錯，也可能是把 CMS 自動產生的模組誤貼回文章內文。

這是一篇把實際上稿問題去脈絡化後留下的工作紀錄。文章不保留特定網站、組織、檔案或人員資訊，只整理一個可以套用到其他內容管理系統的排查方法。

問題表面上像是附件重複

在一次文章內容更新中，我重新整理了圖片替代文字、HTML 結構與無障礙說明。內容發布後，正式頁面的文末卻出現兩次相同的附件下載區塊；把文章還原成舊版內容後，頁面又恢復成只顯示一次。

這種現象很容易讓人先懷疑：

  • 附件是不是被上傳了兩次？
  • HTML 表格是不是複製重複了？
  • 版型或 CSS 是否把同一個區塊顯示兩次？

但真正要先確認的，不是畫面上看到幾次，而是這兩個區塊各自從哪裡來。

真正的原因：同一個區塊有兩個來源

常見 CMS 會把文章內文與附件欄位分開管理。當後台附件欄位有檔案時，系統可能在前台自動產生附件模組，列出檔名、檔案大小或下載操作。

這次的錯誤是重新整理內文時，從已經渲染完成的前台頁面複製 HTML。前台頁面裡原本就包含系統自動產生的附件模組，結果那段表格也被一起貼回文章內文。

於是前台最後同時出現：

  1. 內文中手動貼上的附件表格。
  2. CMS 根據附件欄位自動產生的附件模組。

兩段 HTML 看起來幾乎一樣，所以第一眼像是「系統重複渲染」；實際上是手動內容和系統模組各自輸出了一次。

為什麼舊版內容沒有問題

舊版文章的內文只收尾在正文段落，沒有把前台產生的附件標籤或下載表格存回文章欄位。CMS 只執行一次原生附件模組，因此頁面只出現一個下載區塊。

這個差異提供了很重要的線索：如果舊版正常、新版才開始重複，應該優先比較兩個版本的內文結尾，而不是先假設附件資料本身被複製。

排查順序

1. 先確認重複區塊的輸出來源

不要只看畫面。分別檢查：

  • 後台文章內文是否已經有附件表格或下載標籤。
  • 後台附件欄位是否仍有同一份檔案。
  • 前台 HTML 中兩個區塊的結構、欄位與連結是否完全相同。
  • 版型是否有一個固定的附件模組插槽。

如果內文有一份，附件欄位又能讓系統自動生成一份，就已經找到兩個來源。

2. 比較舊版與新版的內文結尾

先保存目前版本，再和已知正常的舊版比對。重點不是逐字重看整篇文章，而是先搜尋：

  • 附件標題。
  • 下載連結。
  • 檔案大小或下載次數欄位。
  • 系統模組常用的 HTML class 或標籤。

如果這些內容只出現在新版內文，就代表前台渲染結果很可能被誤當成編輯來源。

3. 移除內文中的手動模組

文章內文應只保留正文文字、圖片、連結與必要的語意結構。手動貼入的整段附件下載表格應完整移除，包含標題、表頭、檔案列與包住它的容器。

附件則留在 CMS 原本的附件欄位，交由系統在固定位置產生。不要只刪掉表格標題，卻留下內層連結或空容器，否則可能造成另一種殘留問題。

4. 用最小修改重新驗證

刪除手動模組後，不要同時改動其他 HTML、CSS 或附件設定。重新發布後確認：

  1. 文末只出現一個附件區塊。
  2. 檔名、大小與下載連結仍然正確。
  3. 圖片替代文字與正文結構仍保留。
  4. 桌面與手機版沒有新增空白、跑版或重複容器。

一次只驗證一個原因，才能確定修正真的有效。

內容與系統模組要分開管理

這次最值得留下的不是某一個 CMS 的操作步驟，而是「內容」和「系統模組」的邊界：

  • 文章內文：文字、圖片、連結、表格與語意化 HTML。
  • 附件模組：由附件欄位、版型或後端設定自動產生的區塊。
  • 前台頁面：內文與多個系統模組組合後的最終結果。

前台頁面是輸出結果，不一定是可以直接貼回後台的完整來源。從前台複製整段 HTML 時，必須先排除導覽列、分享按鈕、附件、瀏覽人次與其他共用模組。

可以重複使用的檢查表

下次遇到「正式頁面出現兩份相同區塊」時，可以依序問：

  1. 這個區塊是文章內文產生的，還是系統模組產生的？
  2. 後台是否同時存在內文 HTML 與模組欄位資料？
  3. 新舊版本的內文結尾多了什麼？
  4. 是否從前台複製過已經渲染完成的 HTML？
  5. 能不能只移除手動貼入的模組，再重新驗證？
  6. 修正後是否確認桌面、手機與未登入狀態？

結語

遇到前台重複區塊時，先不要急著把問題歸因為附件上傳錯誤或版型故障。先把「內文來源」和「系統自動生成」分開，再逐一確認每個區塊的責任來源，通常能更快找到真正的重複點。

不要把前台完整輸出當成後台內文來源；先分清正文與模組，再做最小修改。
