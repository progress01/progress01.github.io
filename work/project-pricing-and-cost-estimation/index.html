工作知識｜專案報價與成本估算：把工期、利潤與隱形成本算進去

發表於 2026-09-02 更新於 2026-09-17 分類於 工作知識 文章字數： 3.6k 所需閱讀時間 ≈ 3 分鐘

我重新整理一次專案報價，先把真正成本與可行工期拆開，再談公司預期的利潤。

這是一篇把專案討論去脈絡化後留下的工作紀錄。人物、公司、機關、專案名稱與實際金額都不放進來，只保留在估算報價時可以反覆使用的思考方式。

專案報價不是把工程師的開發時間乘上一個數字，也不是先猜一個客戶可能接受的價格。我現在比較完整的想法是：先找出專案真正會消耗的成本，再確認工期是否真的做得到，最後才把公司預期的利潤放進報價。

一、先把報價拆成成本與利潤

最基本的結構可以寫成：

專案報價＝專案總成本＋公司預期利潤

這句話重點不在公式本身，而是「總成本」不能只算工程師寫程式的時間。只要專案會占用公司的人力、交通、工具、檢測或後續支援，就應該列進成本底線。

專案總成本至少可以分成：

  • 開發人力成本。
  • PM、維運或其他角色的投入成本。
  • 測試、驗證與第三方檢測費用。
  • 會議、出差、駐點與交通成本。
  • 行政處理、工具、帳號與設備耗損。
  • 測試修正、驗收溝通與上線支援。
  • 不可預期變更所需要的緩衝成本。

如果成本底線沒有算完整，後面設定的利潤只是在錯誤的基礎上加上去，報價看似有賺，實際執行時卻可能被額外工時吃掉。

二、毛利率和加成率不是同一件事

估算時很容易把「成本加上利潤」和「設定毛利率」混在一起。兩者的算法不同，最好在報價前先說清楚採用哪一種。

如果是直接加上一筆預期利潤：

報價＝總成本＋目標利潤金額

如果是希望報價達到某個目標毛利率：

報價＝總成本 ÷（1－目標毛利率）

例如總成本是 100，目標毛利率是 20%，報價應是 125，而不是 120。120 是在成本上加 20% 的加成，實際毛利率只有約 16.7%。

因此，文件或會議中如果只寫「利潤抓 20%」，還不夠精確，應該補充是：

  • 成本加成率。
  • 報價毛利率。
  • 或固定的目標利潤金額。

這個定義沒先確認，後面很容易出現大家都以為自己算對，但最後報價不同的情況。

三、工期不能只看功能清單

估算功能時，不能只寫「做一個功能需要幾個月」，而要拆成可以被檢查的工項。例如：

  • 需求理解與規格確認。
  • 資料結構、介面或既有系統調查。
  • 核心功能開發。
  • 前後台串接與權限處理。
  • 測試資料準備。
  • 整合測試與錯誤修正。
  • 使用者驗收與修改。
  • 部署、交接與文件整理。
  • 上線後的觀察與支援。

功能本身可能只需要一段時間，但需求確認、等待資料、第三方協調、驗收反覆修改與上線支援，往往會把整體時程拉長。這些都不是「額外發生的小事」，而是專案工期的一部分。

工程師投入有實際上限

這次估算裡，一個重要的警示是：單一工程師不可能長時間、全年全職只投入同一個專案。即使帳面上把功能加總後可以排出九個月以上，實務上也不代表真的能照那個方式執行。

可以先把單一工程師約六個月的專案投入視為一條警示線：

  • 估到六個月，代表已經相當吃緊，需要檢查是否漏算其他工作。
  • 超過六個月，應該重新檢查功能範圍、投入比例與其他專案的排程。
  • 超過九個月，通常不應直接當成單一工程師可以持續完成的方案，而要考慮拆階段、縮小 MVP 或增加人力。

這不是所有專案都適用的產業定律，而是一個提醒估算者不要只看紙面總工時的警示線。真正要確認的是：工程師每個月能投入多少比例，以及這個比例能不能持續。

四、用人月拆解，而不是只報一個總月份

我比較穩妥的估算方式，是先把功能拆成工項，再估算每個角色的投入比例：

工項 → 預估人天或人月 → 每月投入比例 → 人力成本 → 緩衝 → 專案總工期

例如同一個月裡，工程師可能只投入專案的一部分時間，其他時間還要處理維運、既有案件、臨時問題或內部工作。因此「六個月的工作量」不一定等於「六個月後可以交付」。

估算時要分開看三個數字：

  • 工作量：實際需要多少人天或人月。
  • 投入比例：每個角色每月可以分配多少時間。
  • 日曆工期：從開始到交付實際經過多久。

工作量相同時，只要投入比例不同，日曆工期就會不同。這也是為什麼只用一個總月份報價，通常不足以說明專案是否可行。

五、角色互補不是免費的支援

當工程師的功能開發時間已接近上限，PM、維運或其他角色可能需要承接部分非工程任務，例如：

  • 前期需求整理與規格確認。
  • 測試資料準備與結果彙整。
  • 第三方檢測或驗證的聯繫。
  • 會議安排、問題追蹤與回覆整理。
  • 文件、附件與交付材料的準備。
  • 驗收意見的分類與回報。

這種角色互補可以降低工程師的外部負擔，但它不會讓工作憑空消失。PM 或維運承接的時間也要被估算、被排進工期，必要時也要列入成本。

更需要注意的是，跨角色的協調整合常常比預期更花時間。資訊交接、等待確認、重新說明與來回修改，都可能成為看不見的工時。

所以角色互補的正確理解是：

把任務分配給更適合的角色，而不是把成本消失。

六、隱形成本要逐項盤點

交通與出勤

如果專案需要出差、駐點或往返開會，可以先估算：

預計出勤次數 × 每次來回交通費

交通費不一定只包含車資，也可能包括停車、過路、住宿、餐費與出勤所占用的時間。即使單次金額不大，累積多次後也可能影響專案毛利。

第三方檢測與驗證

只要有外部檢測、認證或驗證，最好直接向檢測單位確認：

  • 初次檢測費用。
  • 補件或複測費用。
  • 所需文件與準備時間。
  • 排程等待時間。
  • 不符合時的修正與再次送驗成本。

第三方費用不應只用過往印象估算，因為規格、檢測範圍與案件條件不同時，費用和時程都可能改變。

行政、工具與支援

容易被忽略的項目還包括：

  • 內部會議與主管審查。
  • 文件整理、簽核與交付格式調整。
  • 軟體、雲端服務或測試環境。
  • 設備、帳號與工具耗損。
  • 上線後的短期觀察與問題回覆。
  • 人員請假、臨時支援與其他案件打斷。

單項看起來都不大，但如果完全不列入估算，就會全部變成未計價的成本。

七、緩衝時間不是多報，而是把不確定性說清楚

成本估算最容易走向兩個極端：一種是完全不留緩衝，另一種是沒有說明依據地任意加價。我比較想採用的做法，是把緩衝對應到具體風險：

  • 需求可能變更。
  • 既有系統文件不完整。
  • 第三方回覆或檢測需要等待。
  • 測試環境與正式環境有差異。
  • 驗收標準尚未完全確認。
  • 資料格式或外部介面可能變動。
  • 人員同時承接其他案件。

緩衝可以分成時間緩衝與金額緩衝，也可以針對高風險工項個別保留。重點是讓團隊知道緩衝在保護什麼，而不是把所有未知都藏在一個看不懂的百分比裡。

八、可以重複使用的估算流程

1. 先做由下而上的成本盤點

先列出所有工作與支出，再加總成專案成本底線：

人力成本

功能工項清單
→ 預估人天／人月
→ 工程師投入比例
→ PM／維運／測試投入
→ 需求、驗收與支援工時
→ 安全緩衝

外部成本

第三方檢測、驗證、授權、服務或設備
→ 直接詢價
→ 確認報價有效期限
→ 確認複測與變更費用

行政與交通

出勤、會議、文件、工具與環境
→ 估算發生次數
→ 乘上單次成本
→ 補上等待與協調時間

2. 再做由上而下的利潤檢查

成本加總後，再確認這個報價是否達到公司希望的毛利或利潤：

  • 目標是固定利潤金額，就用成本加上目標金額。
  • 目標是毛利率，就用成本除以一減毛利率。
  • 若採用加成率，應明確標示為成本乘上一加成率。

由下而上是為了避免漏算，從上而下是為了確認報價符合公司的經營目標。兩種方法要互相檢查，不能只做其中一種。

3. 最後檢查排程是否能落地

報價成立不代表排程成立。要再確認：

  • 單一工程師的投入是否超過可持續上限？
  • PM、維運與測試是否有明確的人力？
  • 需求、資料與第三方回覆的等待時間是否列入？
  • 測試、驗收、修改、部署與交接是否有位置？
  • 如果延遲，合約或交付承諾會怎麼處理？

如果排不下去，就要在報價前處理，而不是等簽約後才發現只能靠加班補洞。

九、估算前可以先問的問題

  • 這次報價的目標是毛利率、加成率，還是固定利潤？
  • 功能是否已拆到可以估算人天或人月？
  • 需求確認、測試、驗收、部署與交接是否都有工項？
  • 工程師每月實際能投入多少比例？
  • PM、維運、測試與行政支援由誰承接？
  • 是否有外部檢測、授權、設備或其他第三方費用？
  • 出勤、交通、會議與等待時間是否列入？
  • 哪些內容是已確認需求，哪些只是目前假設？
  • 需求變更和額外工作要如何處理？
  • 如果估算超過六個月或九個月，是否要拆階段或調整範圍？
  • 報價有效期限與外部成本變動如何處理？
  • 交付後是否包含保固、維護或一定期間的問題回覆？

十、這次最值得保留的提醒

成本估算要同時做到兩件事：想得夠細，又要能實際落地執行。

不能只用 Happy Path 估算，也不能把所有可能發生的事情都堆成一個沒有解釋的高價。我比較信任的方式，是把假設、已知成本、角色投入與不確定性分開寫，讓之後的人知道這個數字是怎麼來的。

這次我想記住的不是「六個月」或「九個月」本身，而是看到這些數字時要停下來問：

這是實際可持續的投入，還是把所有工作都假設成同一個人可以一直做？

如果答案是後者，就要回頭調整功能範圍、投入角色、專案階段或交付承諾。

一句話整理

先把所有會消耗人力與現金的事情算進成本，再用可持續的投入檢查工期，最後才談公司要留下多少利潤。
