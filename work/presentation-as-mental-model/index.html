工作知識｜簡報不是功能清單：先讓人想像事情怎麼運作

發表於 2026-07-09 更新於 2026-09-10 分類於 工作知識 文章字數： 2.7k 所需閱讀時間 ≈ 2 分鐘

這是一篇把工作簡報討論去脈絡化後留下的紀錄。人物、單位、專案名稱與實際資料都不放進來，只保留一個我很常忽略、但之後應該要記得的判斷：簡報不只是把事情說清楚，還要讓聽的人能在腦中想像這件事情怎麼發生。

這次原本想說明網站檢核的執行方式、流程調整與工具輔助。整理過程中，我很容易把既有簡報、工具功能、改版內容、導入時間與需要協作的事項分開處理，結果每一塊看起來都有資料，放在一起卻不像一個完整的故事。

我一開始忽略了什麼？

我常常以為，只要把以下內容列出來，別人就會理解：

  • 現在有哪些工作。
  • 工具可以做哪些事情。
  • 哪些流程有修改。
  • 預計什麼時候開始。
  • 希望其他人提供什麼協助。

但這些其實只是我的資料清單，不一定是對方理解事情的順序。

對我來說，工具、檢查流程與交付格式之間已經有一些連結；對第一次聽的人來說，他可能還不知道：原本的工作畫面是什麼、哪一段最耗時間、工具介入哪裡、工具做完後誰還要判斷，以及這次變動會不會改變他的工作。

所以問題不一定是「內容不夠」，而可能是：

我把自己已經知道的關係，誤以為觀眾也能直接看見。

「讓人可以想像」到底是什麼？

這裡的想像不是做很多插圖，也不是把簡報做得很有氣氛。它比較接近替觀眾建立一個可以在腦中運作的模型。

至少要讓對方能回答：

  1. 事情從哪裡開始？
  2. 中間會經過哪些步驟？
  3. 哪一段原本容易重複、遺漏或卡住？
  4. 新方法改變了哪一段？
  5. 工具處理什麼，人工仍然要判斷什麼？
  6. 最後會產出什麼，交給誰接續？

例如，網站檢核不應只介紹「可以檢查網址、截圖、輸出表格與協助 AI 判讀」，而應該先讓人看見一條工作路徑：

網址或資料進來
→ 前置檢查
→ 人工確認異常
→ 整理截圖與紀錄
→ 回報修正
→ 追蹤交付結果

有了這條路徑，工具功能才有位置。否則每個功能都像獨立的按鈕，觀眾知道它存在，卻不知道為什麼需要它。

簡報的主角不是工具，而是事情如何被完成

這次很容易把簡報做成工具展示：有幾個分頁、可以產生哪些檔案、支援哪些模式、遇到錯誤時怎麼處理。這些內容不是不重要，但如果太早出現，觀眾會先進入「學習操作」的狀態，還沒有理解「為什麼需要這個工具」。

比較好的順序應該是：

工作情境 → 原本的阻力 → 流程如何調整 → 工具放在哪裡 → 人還要做什麼 → 怎麼開始試跑

工具在這裡是流程改善的手段，不是報告的目的。當觀眾先理解工作如何被完成，他才有辦法判斷工具的價值，也比較不會誤會成「有工具之後就完全不用人工」。

同一份簡報，要讓不同的人看見不同的東西

如果聽眾同時包含實際執行者與管理者，簡報不能只選一邊說明。

實際執行者通常想知道：

  • 之後每天或每批要怎麼做？
  • 哪些步驟會被工具協助？
  • 哪些情況仍要自己判斷？
  • 出錯時要看哪份紀錄？

管理者通常更在意：

  • 為什麼要調整？
  • 風險有沒有變得更可控？
  • 目前處於試跑、驗證還是正式導入？
  • 需要哪些資源、決策或協作？

這不是要做兩份互不相干的簡報，而是同一條流程要有不同的閱讀入口。流程圖可以讓執行者看到自己的工作位置，也可以讓管理者看到風險與責任邊界；差別只在旁邊標示的資訊層級不同。

一頁簡報至少要完成一個想像動作

之後整理投影片時，我可以少問「這頁資料夠不夠」，多問：

看完這一頁，觀眾腦中多了哪一個畫面？

一頁可以只完成一個動作：

  • 看見原本的工作如何進行。
  • 看見為什麼要調整。
  • 看見新舊流程差異。
  • 看見工具與人工的分工。
  • 看見接下來的時間點。
  • 看見自己需要協助或決策的地方。

如果一頁同時塞入背景、功能、效益、風險與時程，表面上資訊很完整，實際上反而可能沒有任何一個畫面被記住。

簡報文字也可以改成帶有動作的句子。例如不要只寫「導入半自動化工具」，而是說明：

工具先處理重複性的網址檢查與佐證整理，人工集中在異常判斷、修正確認與交付追蹤。

這句話比列出一串功能更容易讓人想像工作會怎麼改變。

「想像」也包含例外與邊界

如果只展示順利完成的流程，觀眾仍然可能不知道實際使用時會遇到什麼。真正有用的想像，應該包含至少一個例外：

  • 網址無法開啟時，結果會被記錄在哪裡？
  • 來源頁有連結，但目標頁不能直接訪問時，兩者如何分開判斷？
  • 圖片或文字送交外部 AI 前，誰負責確認敏感資料？
  • 工具無法判斷的情況，最後由誰複核？
  • 試跑結果不穩定時，是否仍然回到人工流程？

這些不是為了把簡報變成操作手冊，而是讓觀眾知道流程不是一條只會往前走的直線。當例外被說清楚，大家對工具能做什麼、不能做什麼的期待才會比較接近現實。

可以重複使用的簡報檢查順序

下次遇到需要說明工作調整、工具導入或流程改版的簡報，我可以先按照下面順序整理：

1. 先寫一句話，說明這場簡報要讓人理解什麼

例如：

這次不是介紹一個新工具，而是說明檢核工作如何從重複性前置作業，調整成工具協助、人工複核與可追蹤交付。

這句話可以防止後面的內容一直長成工具功能清單。

2. 畫出現況，不急著放解法

先畫原本的工作路徑，標記：

  • 哪些地方重複。
  • 哪些地方依賴人工記憶。
  • 哪些地方容易漏掉證據。
  • 哪些地方需要不同角色來回確認。

觀眾看見原本的阻力，後面才有機會理解變動的必要性。

3. 用前後對照說明改變

不要只說「流程優化」，而要指出：哪一段被工具協助、哪一段仍然保留人工、哪一段新增了紀錄或驗證。

4. 放入一個具體但不敏感的例子

用一筆抽象化的資料走過流程，讓觀眾看見輸入、判斷、例外與輸出。例子不需要包含真實網址、檔名或內部資料，只要能承載流程即可。

5. 最後才說時程與需要的協助

當大家已經知道事情怎麼運作，再說試跑時間、正式導入條件、需要誰配合，以及哪些問題仍待確認，資訊會比較容易被放進正確的位置。

這次留下來的工作原則

  1. 簡報不是資訊搬運，而是幫觀眾建立一個可以運作的心智模型。
  2. 先讓人看見工作情境，再介紹工具功能。
  3. 流程圖的價值不是漂亮，而是讓人知道自己在哪裡、事情接下來往哪裡走。
  4. 工具要說清楚能做什麼，也要說清楚不能代替什麼。
  5. 一頁投影片最好只完成一個主要的理解動作。
  6. 例外、人工複核與導入邊界，是可信任的簡報內容，不是多餘的負面資訊。

我最想留下的其實不是某一套六頁或八頁的投影片架構，而是這個提醒：

如果我自己腦中已經有一張流程圖，就不能假設觀眾也自動擁有同一張圖。

我需要把那張圖拿出來，先讓人看見事情如何發生，再談我做了什麼改善。

一句話整理

好的工作簡報，不只是讓人聽懂你做了什麼，而是讓人能想像事情原本怎麼運作、改變後怎麼接續，以及自己要在哪裡參與。
