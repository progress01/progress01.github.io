# N+天系列文章維護

Use this skill for requests to create or revise the user's ongoing N+days series, especially posts under `C:\Blog\blog-1988\source\_posts\隨筆\` such as `有工作的第N+4天`.

## Article maintenance

- Edit an existing N+days Markdown file in place so its public URL and accumulated writing remain stable.
- Preserve the user's front matter, headings, and later body unless the user asks for a broader rewrite.
- Treat the article as continuously published and editable; do not move it to `_drafts/` merely because the writing is unfinished.
- Keep the opening excerpt coherent and lead naturally into the rest of the article. The `<!-- more -->` marker is a presentation boundary, not a content boundary.
- For a new article, require a valid `date` and resolve `categories` and `tags` from the currently registered taxonomy in `source/_data/content-categories.yml` and `source/_data/content-tags.yml`; prefer the series' registered primary terms. For an existing article, preserve `date` and `permalink`. Add `updated` only for substantive content changes with a reliable `Asia/Taipei` date, never for formatting or image conversion.

For an existing article, edit in place and preserve unknown front-matter keys, headings, and body sections; do not rebuild it from a new-article example. Keep `date` and `permalink` by default; if the user explicitly requests a correction, apply it and check internal links. For formatting-only or image-conversion changes, keep any existing `updated`; for substantive content changes, set or add one `updated` using a reliable `Asia/Taipei` timestamp, without duplicate fields or moving it backward. If the user explicitly requests correction of an erroneous timestamp, follow that request and verify generated `dateModified >= datePublished`. If a hand-written `description` or `excerpt` exists, confirm it still represents the revised body and do not add either field just to satisfy this check. JSON-LD is generated by the theme; never paste it into the diary. After generation, check `headline`, canonical URL, `datePublished`, `dateModified`, and `image` against the article title, permalink, dates, and actual cover or representative image. See the [project Schema.org notes](<C:/Blog/blog-1988/Schema.org JSON-LD 實作手冊.md>) when needed.

## Fixed excerpt rule

- The text before `<!-- more -->` must use the current N+4 days article as the visual length standard: compact enough to fit the site's feature card without causing an unusually tall card or breaking the surrounding layout.
- Prefer a short, flowing opening of roughly three compact paragraphs and about 120–160 Chinese characters, adjusted for readability rather than treated as a rigid word limit.
- Before finishing an update, check that the excerpt is no longer than the N+4 standard and that it ends at a meaningful transition or question.
- If the article cannot be introduced honestly within that length, do not silently make the card taller. Explain the conflict and discuss whether to shorten the opening or intentionally allow a longer excerpt.

## Verification

After editing, run `npm run verify` from `C:\Blog\blog-1988` (it already includes clean/build/site checks). Confirm that the N+days article is generated and that the homepage/index output contains the compact excerpt while the full article page retains the later sections. If verification is blocked or fails because of unrelated working-tree changes, report the actual command, failure, and affected files; do not claim pass. Do not deploy unless explicitly authorized, and honor authorization already given in the session without asking again.
